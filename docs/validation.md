## Known gaps

- No instructor-verified starter kit or BJT model was supplied; the `NPN_GENERIC` model is a documented generic assumption, and the UI now states “Generic model assumption — not instructor-verified”.
- The user reported `==> Build failed 😞` on the free Render service after adding the `apt-get ... ngspice` Build Command. Root cause: Render free Native environments restrict OS-level package installs, so `apt-get` cannot run. The fix replaces that Build Command with `python scripts/install_ngspice.py && pip install -r requirements.txt`; this file does not claim the new deploy has succeeded because the user deploys separately.
- The deployed Lab 04 page seen by webfetch was the earlier build; no SPICE result from the deployed site is claimed. Local verification used a Windows portable binary, not the Linux conda-forge package; the Render build/runtime is unverified here.
- AC sweep is fixed at 1 Hz–10 MHz and does not follow the source-frequency input (documented above).
- AC plot root cause and fix: the sweep is logarithmic (`.ac dec 20 1 10Meg`) but `plots.py` drew a linear x-axis, so 138 of 141 points were compressed into the leftmost pixels and the trace looked like a vertical line plus a flat line. `line_svg(..., log_x=True)` now maps x to log10, adds decade gridlines/labels, and moves the y-axis label off the title; `app.py` uses it only for AC. Transient stays linear and was re-verified with a real run (208 points, two series).
- Reviewer findings fixed after `a0948fd` (AC 3-column plotting crash, paginated parser truncation, Jinja `dict.values` collision, unit-selector reset, missing model-assumption text) were pushed in `75c671c`; the real-ngspice `.op` parser fix, initial Render Build Command and B2–B6 evidence were pushed in `6c4a716`. the user-level install fix (micromamba script + local binary discovery) was pushed in `7037aae` and is covered by 3 new tests.
